03 — Solution

One routing layer. Consistent rules at every boundary.

Japolic sits between services as a lightweight, stateless routing plane. It holds the protocol negotiation, policy enforcement, and failure handling that currently lives scattered across application codebases. Each rule is versioned in config, observable in structured logs, and deployable in under two minutes.

01

Protocol Arbitration

Translates between conflicting internal protocols at the request boundary — HTTP/2, gRPC, WebSocket — without requiring contract changes from either service.

SCOPE: HTTP/2 · gRPC · WEBSOCKET
02

Policy-Gated Traffic

Evaluates each request against a versioned ruleset before it reaches the destination. Rules are written in a declarative config file, diffed in CI, and deployed atomically.

CI/CD: ATOMIC DEPLOY · VERSIONED DIFFS
03

Structured Failure Routing

When a downstream service returns a defined error class, Japolic routes to a fallback path or returns a structured error payload instead of surfacing a raw upstream fault.

PAYLOAD: JSON/GRPC STRUCTURED ERROR ENVELOPE
Architectural Boundaries

04 — Feature: Policy Plane

Rules live in config.
Violations surface in logs.

Every request crosses a policy boundary. Japolic evaluates versioned rules before the request reaches its destination — and returns a structured error if it fails, not a raw 500.

01
Ingress Boundary

Request arrives from source service. Japolic intercepts it before it reaches the destination — zero application code change required.

02
Policy Evaluation

Rules defined in japolic.rules are evaluated in order: source allowlist, required headers, response schema, idempotency constraints.

03
PASS → Delivery

All checks pass. Request is forwarded and protocol-translated if needed (REST→gRPC, HTTP/2→WebSocket). Destination receives a clean, verified payload.

04
FAIL → Structured Error

Violation returns PROTO_VIOLATION_4031 to the caller. No raw upstream fault. No silent bad data. Every violation is logged with rule ID and latency.

CASE 01 · FINTECH

Platform Team at a Fintech

22 internal services · 40 engineers

Cascading timeout failures caused by uncoordinated client retries and missing idempotency headers across caller services.

POLICY INTERVENTION:

Platform team defined a single global retry-policy rule enforced at the Japolic boundary. Header requirements and idempotency keys are validated before dispatch; caller services purged custom retry loops and consumed Japolic structured error payloads.

CASE 02 · PROTOCOL MIGRATION

Infrastructure Lead

6 services · REST → gRPC

Migrating backend services across differing protocol versions simultaneously, requiring costly and brittle mock services.

POLICY INTERVENTION:

Japolic's protocol arbitration layer translated gRPC calls to REST for legacy endpoints during the migration window. Calling services were updated once to speak pure gRPC, with Japolic managing downward translation until each provider completed migration.

✓ Upstream callers decoupled from provider roadmap ✓ 3 mock internal services decommissioned early
